# 배달 진행 타임라인 계획 (부르미 실시간 배송 화면)

## 배경

부르미 실시간 배송 화면(`frontend/src/pages/delivery-detail/ui/RealDeliveryTracking.tsx`)에서
지도 아래 흰색 카드("실시간 상태" + 굵은 상태 텍스트 한 줄)를, 배민 배달 화면처럼
4단계 진행 타임라인으로 교체한다.

## 대상 화면 / 위치

- 파일: `frontend/src/pages/delivery-detail/ui/RealDeliveryTracking.tsx`
- 교체 지점: 404~414번째 줄의 `Card`(핀 아이콘 + "실시간 상태" 라벨 + `{view.title}`)

```tsx
<Card className="flex items-center gap-3">
  <span className="... rounded-pill bg-teal-50 text-teal-700">
    <Icon name="pin" size={18} />
  </span>
  <div className="flex flex-col">
    <span className="text-2xs text-muted">실시간 상태</span>
    <span className="text-md font-bold text-navy-900">{view.title}</span>   {/* ← 이 자리를 4단계 타임라인으로 */}
  </div>
</Card>
```

- 지도 위 `<h1>{view.title}</h1>`(373~380번째 줄)을 그대로 둘지, 없앨지는 미확정 — 결정 필요.

## 단계 구성

픽업 시작 → 픽업 완료 → 배달 시작 → 배달 완료. 완료된 단계는 teal, 아직 안 된 단계는 회색.

## 상태 매핑

백엔드 `DeliveryStatusResponseDtoStatus`를 그대로 재사용(백엔드 변경 없음). 드리미가 픽업사진을
올려서 픽업 완료 처리하는 시점에 "픽업 완료"와 "배달 시작"이 동시에 완료 처리된다(현재 백엔드가
이 둘을 구분하는 별도 이벤트를 갖고 있지 않기 때문).

| 백엔드 status | 픽업 시작 | 픽업 완료 | 배달 시작 | 배달 완료 |
| --- | --- | --- | --- | --- |
| `PICKUP_NORMAL` / `PICKUP_DELAYED` (초기 진입) | ✅ | ⬜ | ⬜ | ⬜ |
| `DELIVERING` (픽업사진 업로드로 완료 처리된 시점) | ✅ | ✅ | ✅ | ⬜ |
| `DELIVERED` | ✅ | ✅ | ✅ | ✅ |

## 구현 개요

1. `frontend/src/shared/ui/`에 새 타임라인 컴포넌트 추가(예: `DeliveryTimeline`) — 4개 점 + 연결선,
   done 여부에 따라 teal/회색.
2. `RealDeliveryTracking.tsx`가 이미 구독 중인 `status` 값으로 4단계 done 배열을 계산.
3. 위 `Card`의 텍스트 자리를 이 컴포넌트로 교체.

## 미확정 사항

- 지도 위 `<h1>{view.title}</h1>`도 없앨지 여부.
- 드리미(배달원) 쪽 추적 화면(`DeliveryTrackScreen.tsx`)도 같은 걸 적용할지 여부 — 이번 스코프는
  부르미 화면만.

## (이후 변경) 실제로는 3단계로 축소돼서 구현됨

위 계획은 4단계(픽업 시작/픽업 완료/배달 시작/배달 완료)였는데, 실제 구현은 "부름 접수 → 픽업 완료 →
드림 완료" 3단계로 줄었다. 픽업 완료와 배달 시작이 백엔드에서 항상 동시에 완료 처리되는 같은
이벤트라 하나로 합쳤다. 각 단계 완료 시각도 실제로 표시하도록 붙였다:

| 단계 | 시각 출처 |
| --- | --- |
| 부름 접수 | `MATCHING.accepted_dtm`(부르미가 드리미를 확정한 순간) |
| 픽업 완료 | `DELIVERY.delivery_start_dtm`(픽업 완료=배달 시작 동시 이벤트) |
| 드림 완료 | `DELIVERY.delivery_end_dtm` |

완료된 단계 라벨 오른쪽엔 점선 + 시각("오전/오후 h시 m분")을 표시한다(`DeliveryTimeline` 컴포넌트,
`timestamps` prop). 단계 간 세로 간격은 108px(고정 픽셀).

## 다음 단계: 상태 사이 진행률을 걷는 아이콘으로 표시

배민 배달 화면처럼, 완료된 상태와 다음 상태 "사이"에서 드리미가 얼마나 왔는지를 걸어가는/이동하는
아이콘으로 보여주고 싶다. 지금은 상태 사이 간격이 고정 픽셀이라 "몇 % 왔는지" 개념 자체가 없다.

### 검토한 방법

1. **직선거리 비율**: 픽업지↔배송 출발지, 배송 출발지↔배송 도착지를 직선거리로 계산해서 화면상
   두 점 사이 진행률로 씀. 구현은 쉽지만 실제로는 도로를 따라 꺾어 가므로 직선거리 비율이 실제
   진행률과 어긋날 수 있음(특히 방향을 꺾는 구간).
2. **시간 기반**: 구간 시작부터 경과 시간 / 예상 소요 시간으로 진행률 추정. 구현은 제일 쉬우나,
   이 화면엔 이미 드리미의 실제 GPS 위치가 지도에 실시간으로 표시되고 있어서, 정체·정차 등으로
   실제 위치와 안 맞으면 같은 화면에서 지도와 타임라인이 서로 다른 얘기를 하게 됨(신뢰도 저하).

### 추천안: 백엔드가 이미 계산해주는 "남은 실제 경로" 길이 활용

`deliveryRoutePath`/`routePath`(카카오 길찾기로 계산된 실제 도보 경로, 드리미 위치 갱신마다
다시 계산되어 SSE로 갱신됨)의 좌표 배열 길이를 그대로 합산하면 "지금 시점에 남은 실제 이동 거리"가
나온다. 구간 시작 시점의 전체 경로 길이 대비, 매 위치 갱신마다 새로 받는 "남은 경로" 길이 비율로
진행률을 계산하면:

- 실제 도로 기준이라 직선거리보다 정확
- 지도에 그려지는 것과 동일한 데이터라 지도와 타임라인이 항상 같은 값을 보여줌
- 좌표 배열 길이(haversine 합산)만 계산하면 되니 점-대-폴리라인 투영 같은 복잡한 기하 계산 불필요

**결정 대기 중** — 이 방향으로 갈지, 시간 기반으로 먼저 간단히 해볼지 아직 안 정함.
