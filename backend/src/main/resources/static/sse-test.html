3. 매칭 조작 (디버그 API)

라우팅 규칙: SSE 이벤트는 대상 사용자 UUID로 라우팅됩니다.
• dreami_info → 주문 owner boormiId. 아래 "주문 boormiId"를 내 userId로 두면 이 브라우저에서 수신됩니다.
• offer_popup / offer_closed / boormi_rejected → 각 드리미의 id. 디버그 등록은 랜덤 UUID라 이 브라우저로는 안 옵니다(서버 로그로 확인). 상태 전이는 정상 동작합니다.

4. Timeout / 재매칭 디버그

실제 DelayQueue timeout(OFFER_TTL/BOORMI_OFFER_TTL)을 기다리지 않고, 아래 표의 D만료/B만료 버튼으로 ExpireDreamiOffer/ExpireBoormiOffer를 즉시 트리거해 재매칭 로직을 테스트할 수 있습니다. 이미 종료된 오퍼에 뒤늦게 눌러도(stale timeout 재현) 서버가 무시하거나 상태 전이 예외만 로그로 남기고 무시합니다.
👉 등록/거절/취소/만료 등으로 드리미나 주문이 풀리면, matching.batch-window(기본 1s) 주기로 반복 실행되는 배치 매칭 사이클이 다음 회차에서 자동으로 재배정을 시도하므로, 별도 트리거 없이 방(offers) 조회를 잠깐 뒤에 다시 눌러보는 것만으로 재매칭 결과를 확인할 수 있습니다.
