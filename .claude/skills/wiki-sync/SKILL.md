# 노션 → GitHub 위키 동기화

팀은 관련 서류를 노션에 쓴다. 그런데 개발 문맥은 GitHub 안에 있으니, 문서를 위키로도 미러링해두면
코드 보다가 바로 참고할 수 있다. 문제는 노션을 위키에 **그냥 붙여넣으면 깨진다**는 것 —
노션은 `<callout>`, `<columns>`, `<span color>` 같은 자체 서식으로 내용을 주는데
GitHub 위키는 순수 GFM(GitHub Flavored Markdown)만 렌더링한다.

이 스킬의 일은 그 간극을 메우는 거다. **노션에서 읽어 → 위키가 이해하는 MD로 다듬어 → push.**
단순 복사가 아니라 "위키 페이지로서 읽을 만하게" 만드는 게 핵심이다.

---

## 사전 조건 (처음 한 번만)

이 두 가지가 안 돼 있으면 스킬이 동작하지 않는다. 실행 초반에 확인하고, 안 됐으면 사용자에게 알려라.

1. **Notion MCP 연결** — `claude mcp list` 에서 `notion` 이 `Connected` 여야 한다.
   `Needs authentication` 이면 `/mcp` 로 인증하라고 안내.
2. **위키 저장소 초기화** — GitHub 위키는 웹에서 **첫 페이지를 한 번 만들어야** `.wiki.git` 이 생긴다.
   그 전엔 clone/push가 "Repository not found" 로 실패한다. 실패하면 사용자에게
   `github.com/<owner>/<repo>/wiki → Create the first page` 를 먼저 하라고 안내.

---

## 1. 대상 페이지 확인

사용자가 노션 페이지 URL(또는 ID)을 준다. 안 줬으면 물어라 — 이 스킬은 URL을 직접 받는 방식이다.

여러 개를 한 번에 줄 수도 있다. 그러면 각각을 개별 위키 페이지로 처리한다.

> **DB 통째 순회는 피하라.** 이 워크스페이스 플랜에서 `query_data_sources`(데이터베이스 행 목록 읽기)는
> 무료 체험 제한 상태다. "공식 문서 보관함 전부 올려줘" 같은 요청이 오면, DB를 순회하는 대신
> 사용자에게 올릴 **페이지들의 URL을 달라**고 하거나, 이미 동기화한 목록(`synced-pages.md`, 아래 5번)을
> 쓰라고 안내해라. 개별 페이지를 URL로 읽는 `notion-fetch` 는 제한이 없다.

---

## 2. 노션에서 읽기

`mcp__notion__notion-fetch` 에 URL/ID를 넘겨 내용을 가져온다. 반환은 노션 확장 마크다운이다.
`<properties>` 의 `title` 이 문서 제목이다. `<content>` 안쪽이 본문.

`<ancestor-path>` 블록은 노션 내부 위치 정보라 **위키에는 필요 없다. 통째로 버려라.**

---

## 3. 위키용 마크다운으로 변환

노션 전용 태그를 GFM로 바꾼다. 아래가 실제로 나오는 것들이다 — 기억이 아니라 이 표를 따르되,
표에 없는 태그가 나오면 "의미를 살린 가장 단순한 GFM" 원칙으로 처리해라.

| 노션 서식 | 위키(GFM) 변환 |
| --- | --- |
| `<callout>…</callout>` | `> ` 인용블록으로. 안의 `###` 제목은 그대로 살림 |
| `<columns><column>…` | 컬럼 개념은 버리고 **위→아래 순서로 이어붙임**. 위키엔 단 나눔이 없다 |
| `<span color="red">텍스트</span>` | 색은 버리고 텍스트만. 강조가 중요하면 `**텍스트**` |
| `<mention-page url=…>이름</mention-page>` | 그 페이지도 위키에 있으면 `[[이름]]`, 아니면 일반 텍스트 `이름` |
| `<page url=…>이름</page>` | 위 mention과 동일 규칙 |
| `<mention-date start="2025-11-14"/>` | `2025-11-14` 평문으로 |
| `<database inline=…>이름</database>` | 위키로 못 옮긴다. `> 📊 (노션 DB: 이름 — 노션에서 확인)` + 원본 링크 |
| `<br>` | 줄바꿈(개행)으로 |
| `<empty-block/>` | 삭제 |
| `` `백틱` `` 안의 텍스트 | 그대로 인라인 코드 유지 |
| 이미지/첨부파일 | 노션 서명 URL은 만료된다. 위키 `_images/` 등에 넣기 어려우면 원본 노션 링크로 두고 "이미지는 노션 참조" 주석 |

변환하면서 판단이 필요한 지점:

- **본문이 거의 없고 링크/DB 임베드뿐인 페이지**(예: 대시보드성 페이지)는 위키에 옮겨봐야 빈 껍데기다.
  그럴 땐 옮기지 말고 "이 페이지는 내용이 링크/DB뿐이라 위키로 옮기면 껍데기만 남는다"고 알리고
  사용자가 정하게 해라.
- **문서 상단에 원본 링크를 남겨라.** 위키는 사본이고 노션이 원본이다. 헷갈리지 않게
  맨 위에 `> 📄 원본(노션): <url> — 최종 동기화 YYYY-MM-DD` 한 줄을 붙인다. 날짜는 오늘 날짜.

---

## 4. 위키 페이지명 정하기

GitHub 위키는 **파일명이 곧 페이지 제목**이다. 노션 제목을 파일명으로 쓴다.

- 제목 앞의 이모지(`📄 프로젝트 제안서`)는 파일명에서 떼라 → `프로젝트 제안서.md`. 한글 파일명 가능하다.
- 파일명에 `/ \ : * ? " < > |` 는 못 쓴다. 있으면 `-` 로 치환.
- `Home.md` 는 위키 첫 화면이다. 함부로 덮지 마라.

---

## 5. 저장소에 반영

`gh` CLI는 이 환경 PATH에 없을 수 있다. **순수 git으로 `.wiki.git` 을 직접 다룬다.**

대상 레포를 먼저 정한다. 이 프로젝트는 `origin` 이 개인 포크(`seoki180/...`)이고 실제 협업은
`softeerbootcamp-8th/WEB-Team3-NaengSam` 이다 (`docs/git-convention.md`, `issue-writer` 스킬 참고).
**위키는 팀이 함께 보는 것이니 팀 레포(`softeerbootcamp-8th`)를 기본 대상**으로 하되,
push 권한이 없어 실패하면 사용자에게 어느 레포로 할지 확인해라.

작업은 스크래치패드 같은 임시 폴더에서 한다 (프로젝트 트리를 더럽히지 않게):

```bash
WIKI=<임시경로>/wiki && rm -rf "$WIKI"
git clone https://github.com/softeerbootcamp-8th/WEB-Team3-NaengSam.wiki.git "$WIKI"
# 변환한 MD를 $WIKI/<페이지명>.md 로 씀 (Write 도구 사용)
git -C "$WIKI" add -A
git -C "$WIKI" commit -m "Docs : 노션 <문서명> 위키 동기화"
git -C "$WIKI" push
```

- `clone` 이 "Repository not found" 면 → 위키 미초기화(사전 조건 2). 안내하고 멈춰라.
- 커밋 메시지는 팀 컨벤션(`Docs : …`)을 따른다.

### push 전에 반드시 확인받아라

**자동으로 push하지 마라.** 위키는 팀 전체가 보고, 한번 올라가면 히스토리에 남는다.
변환된 MD를 대화창에 보여주고 "이대로 위키에 올릴까요?" 확인을 받은 뒤 push한다.
여러 페이지면 어떤 파일들이 새로/수정되는지 목록으로 보여줘라.

---

## 6. 동기화 목록 남기기 (다음을 편하게)

사용자가 매번 URL을 다시 붙여넣는 건 번거롭다. 한 번 동기화한 페이지는
`.claude/skills/wiki-sync/synced-pages.md` 에 `| 위키페이지명 | 노션URL | 마지막동기화일 |` 로 기록해둔다.
다음에 "위키 전부 갱신" 하면 이 목록의 URL들을 다시 읽어 갱신하면 된다 (DB 순회 없이).

파일이 없으면 처음 동기화할 때 만들고, 있으면 항목을 갱신/추가한다.
